# Запуск сервера Leafy на DigitalOcean — пошагово

Эта инструкция для человека, который делает это впервые. Команды из серых блоков
копируете и вставляете в терминал сервера целиком. Под каждой командой написано,
что она делает.

## Что получится в итоге

На вашем VPS будут работать 4 программы, каждая в своём контейнере Docker:

| Контейнер    | Что делает                                                                                              |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| **caddy**    | «Дверь» в сервер: принимает запросы из интернета, включает HTTPS (замок 🔒) и сам продлевает сертификат |
| **api**      | Наш сервер приложения (Next.js): вход, сканы, растения, посты                                           |
| **postgres** | База данных: пользователи, растения, посты                                                              |
| **redis**    | Быстрая память для кэша и лимитов (например, 10 сканов в день)                                          |

Из интернета видна только Caddy (порты 80 и 443). База и Redis закрыты: к ним
обращается только наш сервер изнутри.

## Что нужно заранее

- **IP-адрес** вашего Droplet (виден в панели DigitalOcean).
- **Домен** (например, `myleafy.com`). Сервер будет на поддомене `api.myleafy.com`.
- **Ubuntu 22.04 или 24.04** на сервере. При другой системе скажите, и я поправлю команды.
- Желательно **2 ГБ RAM** или больше. При 1 ГБ шаг 4 (swap) обязателен.

---

## Шаг 1. Направить домен на сервер

Надо сказать интернету: «`api.myleafy.com` — это мой сервер».

Зайдите туда, где купили домен (или в DigitalOcean → Networking → Domains, если
домен подключён туда), и добавьте запись:

| Тип | Имя (Host) | Значение          | TTL          |
| --- | ---------- | ----------------- | ------------ |
| `A` | `api`      | IP вашего сервера | по умолчанию |

Запись начинает работать через время от 5 минут до пары часов. Проверить можно на
https://dnschecker.org: введите `api.myleafy.com`, там должен показаться ваш IP.

## Шаг 2. Подключиться к серверу

Откройте терминал: на Windows это **PowerShell**, на Mac — **Терминал**.

```bash
ssh root@ВАШ_IP
```

_Подключает вас к серверу. При первом входе спросит «Are you sure…?» — напишите
`yes`. Дальше введите пароль или войдёте по SSH-ключу (зависит от того, как
создавали Droplet)._

Всё, что ниже, выполняется уже **на сервере**.

## Шаг 3. Обновить систему

```bash
apt update && apt upgrade -y
```

_Скачивает и ставит обновления безопасности. Займёт 1–3 минуты. Если появится
розовое окно с вопросом — нажмите Enter (оставить как есть)._

## Шаг 4. Добавить swap (запасную память)

Сборка сервера требует много памяти. Swap — это «запасная память» на диске, чтобы
сборка не упала на маленьком сервере.

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

_Первая строка создаёт файл 2 ГБ и включает его как память. Вторая делает так,
чтобы swap включался после перезагрузки._

Проверка: `free -h` — в строке `Swap` должно быть `2.0Gi`.

## Шаг 5. Включить файрвол

Файрвол — это «охранник», который пропускает только нужные двери.

```bash
ufw allow OpenSSH
ufw allow 80
ufw allow 443
ufw --force enable
```

_Разрешаем SSH (чтобы вы могли заходить), 80 и 443 (сайт и HTTPS). Всё остальное
закрыто._

⚠️ Строку `ufw allow OpenSSH` не пропускайте, иначе вы закроете сами себе вход на сервер.

## Шаг 6. Установить Docker

```bash
curl -fsSL https://get.docker.com | sh
```

_Официальный установщик Docker. Займёт около минуты._

Проверка: `docker --version` должна показать версию.

## Шаг 7. Скачать код проекта

Репозиторий на GitHub, скорее всего, **приватный**, поэтому серверу нужен «ключ
только для чтения» (deploy key).

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519 -C "leafy-server"
cat ~/.ssh/id_ed25519.pub
```

_Создаёт ключ и показывает его публичную часть (строку, начинающуюся с
`ssh-ed25519`). Эта часть не секретная._

Скопируйте эту строку и добавьте её на GitHub: репозиторий **App-grass → Settings →
Deploy keys → Add deploy key**. Название: `DigitalOcean`. Галочку «Allow write
access» **не** ставьте. Нажмите Add key.

Теперь скачайте код:

```bash
git clone -b claude/eloquent-carson-d4ilid git@github.com:weart1/App-grass.git /opt/leafy
```

_Скачивает проект в папку `/opt/leafy`. На вопрос `Are you sure…?` ответьте `yes`._

> Когда мы сольём работу в ветку `main`, команду поменяем на `-b main`.

## Шаг 8. Заполнить настройки (файл `.env`)

`.env` — это файл с секретами сервера (пароли, ключи). Он хранится **только на
сервере** и никогда не попадает на GitHub.

```bash
cd /opt/leafy/deploy
cp .env.example .env
```

_Делает копию шаблона._

Сгенерируйте секреты (каждая команда печатает случайную строку):

```bash
echo "POSTGRES_PASSWORD=$(openssl rand -hex 24)"
echo "AUTH_SECRET=$(openssl rand -base64 32)"
echo "CRON_SECRET=$(openssl rand -hex 24)"
```

Откройте файл в редакторе:

```bash
nano .env
```

Заполните:

- `API_DOMAIN=api.myleafy.com` (ваш поддомен из шага 1);
- `POSTGRES_PASSWORD=…`, `AUTH_SECRET=…`, `CRON_SECRET=…` — вставьте строки из
  предыдущей команды;
- `GOOGLE_WEB_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` — из Google Cloud (если уже
  создали; можно добавить позже);
- остальное пока оставьте пустым.

Сохранить в nano: **Ctrl+O**, затем **Enter**. Выйти: **Ctrl+X**.

```bash
chmod 600 .env
```

_Делает файл читаемым только для администратора._

## Шаг 9. Запустить

```bash
/opt/leafy/deploy/scripts/deploy.sh
```

_Скачивает свежий код, собирает сервер и запускает все 4 контейнера. Первый раз
займёт **3–7 минут**, потом быстрее._

В конце увидите таблицу: у `api`, `postgres`, `redis` в статусе должно быть
`healthy` (может понадобиться подождать ~30 секунд и выполнить
`cd /opt/leafy/deploy && docker compose ps`).

## Шаг 10. Проверить

Откройте в браузере: `https://api.myleafy.com/api/health`

Должно появиться:

```json
{ "status": "ok", "service": "leafy-api", "version": "abc1234", "time": "…" }
```

Замок 🔒 в адресной строке означает, что HTTPS работает. 🎉

## Шаг 11. Ежедневные копии базы

```bash
(crontab -l 2>/dev/null; echo "0 3 * * * /opt/leafy/deploy/scripts/backup-db.sh >> /opt/leafy/deploy/backups/backup.log 2>&1") | crontab -
```

_Каждую ночь в 3:00 сохраняет копию базы в `/opt/leafy/deploy/backups/` и хранит
последние 14 дней._

💡 Дополнительно рекомендую включить **Backups** у Droplet в панели DigitalOcean
(+20% к цене). Это копия всего сервера на случай поломки.

## Полезные команды на каждый день

Все команды выполняются из папки `/opt/leafy/deploy` (`cd /opt/leafy/deploy`).

| Задача                          | Команда                                    |
| ------------------------------- | ------------------------------------------ |
| Обновить сервер до свежего кода | `./scripts/deploy.sh`                      |
| Посмотреть, всё ли работает     | `docker compose ps`                        |
| Логи сервера (выход: Ctrl+C)    | `docker compose logs -f api`               |
| Логи HTTPS/Caddy                | `docker compose logs -f caddy`             |
| Перезапустить сервер            | `docker compose restart api`               |
| Остановить всё                  | `docker compose down` (данные сохраняются) |
| Сделать копию базы сейчас       | `./scripts/backup-db.sh`                   |

⚠️ **Никогда не запускайте `docker compose down -v`**: флаг `-v` удаляет базу данных.

## Если что-то пошло не так

| Проблема                                        | Что делать                                                                                                                                   |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Браузер пишет «небезопасно», нет замка          | Домен ещё не указывает на сервер (проверьте шаг 1 через dnschecker) или закрыты порты 80/443 (шаг 5). Посмотрите `docker compose logs caddy` |
| Сборка оборвалась со словом `Killed`            | Не хватило памяти: проверьте swap (шаг 4)                                                                                                    |
| `Permission denied (publickey)` при `git clone` | Deploy key не добавлен на GitHub (шаг 7)                                                                                                     |
| `api` не становится `healthy`                   | `docker compose logs api` — пришлите мне вывод (уберите из него пароли)                                                                      |
